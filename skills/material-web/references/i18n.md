# Internationalization

The library ships **no translation catalogs**. Every user-facing default string is a plain-English message resolved at call time through a three-tier chain, and every component also exposes label props that override all of it.

## How a string resolves

1. **Page-provided locale globals** — if the page sets `window.django.jsi18n_initialized = true` and provides `window.gettext` / `window.pgettext` / `window.get_format`, those are used. (The `django` flag name is historical; any backend can set it — see below.) This lets the page's own message catalog be the single source of truth.
2. **`Intl`** — month/weekday names, first day of week, number separators, and currency placement derive from `Intl.*` using the page locale (`<html lang>`).
3. **English defaults** — the inline message itself ("OK", "Cancel", "No results", …).

On top of that, every component exposes label props with empty defaults — `ok-label`, `no-results-label`, `available-label`, `clear-label`, etc. **A prop you set always wins** over all three tiers.

## Providing catalogs and formats (any backend)

Define the globals **before** the components bundle loads, then set the flag:

```html
<html lang="fr">
<head>
  <script>
    window.gettext  = (s) => MY_CATALOG[s] ?? s;
    window.pgettext = (ctx, s) => MY_CATALOG[`${ctx}\x04${s}`] ?? window.gettext(s);
    window.get_format = (name) => MY_FORMATS[name];   // e.g. 'DATE_INPUT_FORMATS'
    window.django = { jsi18n_initialized: true };
  </script>
  <script type="module" src="/static/material/material.esm.js"></script>
</head>
```

`get_format` is what the date/time and number fields consult for input formats, first day of week, and decimal/thousand separators. Without these globals, formatting falls back to `Intl` for the page `lang` — fully functional out of the box, no setup.

## Which components read formats

- Date/time fields (`material-date-field`, `material-date-range-field`, `material-time-field`, `material-datetime-field`, `material-calendar`) honor the page's date/time input formats and first-day-of-week.
- `material-number-field` honors decimal/thousand separators (and currency symbol/placement via `Intl` for its `currency` mode).

When no locale globals are present, all of these follow `<html lang>` through `Intl` automatically — you only wire globals when you need a specific catalog or non-`Intl` format rules.

## Setting a label directly

Simplest override when you just need one string in the current language:

```html
<material-autocomplete no-results-label="Aucun résultat" loading-label="Chargement…"></material-autocomplete>
```
