# Internationalization

The library ships **no translation catalogs**. Every user-facing string is a
plain-English `msgid` resolved at call time through a three-tier chain
(`src/utils/i18n.ts`):

1. **Django jsi18n** — if `window.django.jsi18n_initialized` is true, the
   page-loaded `gettext` / `pgettext` / `get_format` are used. Your project's
   `.po` catalogs are the single source of truth.
2. **Intl** — locale data (month/weekday names, first day of week, number
   separators, currency placement) derives from `Intl.*` using the page
   locale (`<html lang>`, which Django's `LocaleMiddleware` sets).
3. **English defaults** — the inline msgid itself ("OK", "Cancel",
   "No results", …).

On top of that, every component exposes label props (`ok-label`,
`no-results-label`, `available-label`, …) with empty defaults — a prop you
set always wins over all three tiers. Nothing is baked in.

## Django setup

Expose the JavaScript catalog and load it **before** the components bundle:

```python
# urls.py
from django.views.i18n import JavaScriptCatalog

urlpatterns = [
    path("jsi18n/", JavaScriptCatalog.as_view(), name="javascript-catalog"),
]
```

```html
<html lang="{{ LANGUAGE_CODE }}">
  ...
  <script src="{% url 'javascript-catalog' %}"></script>
  <script type="module" src="{% static 'material/material.esm.js' %}"></script>
```

That's the whole integration:

- **Strings** — `gettext('Select date')` etc. resolve through your catalog.
- **Formats** — date/time fields honor `DATE_INPUT_FORMATS`,
  `TIME_INPUT_FORMATS`, `DATETIME_INPUT_FORMATS`, `FIRST_DAY_OF_WEEK`;
  material-number-field honors `DECIMAL_SEPARATOR` / `THOUSAND_SEPARATOR`
  (all via `get_format`). Formats follow the active language automatically
  when `USE_I18N`/`FORMAT_MODULE_PATH` are configured — no component props
  needed.

## Translating the component msgids

The msgids are ordinary English strings inside the shipped JS. To pull them
into your project catalog, either add the library dist to `makemessages`:

```bash
django-admin makemessages -d djangojs -l ru \
    --ignore "node_modules/*" \
    --symlinks  # plus an entry point that includes the dist, or:
```

or extract the list directly and keep it in a tracked stub file the
`makemessages` run scans:

```bash
grep -rhoE "gettext\('[^']+'\)" node_modules/@robustarush/material/dist \
    | sort -u > locale/material_msgids.js
```

Msgids never change silently within a minor version; new components add new
msgids (listed in release notes).

## Non-Django backends

Provide the same three globals before the bundle loads and set the flag —
component code doesn't care who filled them:

```html
<script>
  window.gettext = (s) => MY_CATALOG[s] ?? s;
  window.pgettext = (ctx, s) => MY_CATALOG[`${ctx}${s}`] ?? window.gettext(s);
  window.get_format = (name) => MY_FORMATS[name];
  window.django = { jsi18n_initialized: true };
</script>
```

Without any of this the components fall back to Intl + English — fully
functional out of the box.
